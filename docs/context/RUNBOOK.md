# 操作手册

## 本地开发

前置条件：在项目根目录，具备 Node.js/npm；本地 API 按既有说明要求使用 Node.js 22+（本次未做安装验证）。依赖安装会改变本地环境，先核对任务需要及锁文件差异。

1. 按 README 安装并启动前端。`dev` 脚本使用 `vite --host`，会开放网络监听。
2. 需要博客或旅行 API 时，在另一终端运行 `npm run dev:api`。根据 [开发服务](../../scripts/dev-api.mjs) 与 [Vite 配置](../../vite.config.js)，服务监听 `127.0.0.1:8788`，前端代理 `/api` 到它。
3. 本地 API 先继承进程环境，再加载 `.env.local`，最后加载 `.dev.vars`，后者覆盖前者。不要为核对流程输出这些文件或凭证值。
4. 文章配置需 `NOTION_TOKEN`、`NOTION_DATABASE_ID`；额外到访记录需 `NOTION_PLACES_DATABASE_ID`、`NOTION_VISITS_DATABASE_ID`，并共享相应数据库给 integration。护照数据库映射和维护约束见 [既有交接](../passport-preview-handoff.md#迁移与技术维护)。实际凭证及权限是否齐备待核实。既有本地运行说明指出：未配置额外数据库时仍显示文章生成的足迹；Vercel 与 Cloudflare 需分别在平台设置变量。这些行为本次未运行验证。

验证：确认终端启动结果；按任务检查相关 API 的成功、失败和空状态。旅行功能遵守 [项目验证规则](../../AGENTS.md#文档职责与验证)，页面效果由用户查看；服务启动不等于端到端验收。

## 测试与构建

- `npm run check:source`：核对源码相对导入、全部 Vue 脚本与模板绑定，也覆盖当前未在首页使用的博客列表；不启动浏览器。
- `npm test`：按 [包脚本](../../package.json) 执行 Node 测试；功能改动先定位相关用例，再按影响决定是否跑全套。
- `npm run build`：执行前端构建和 Sites Worker 打包。输出关系见 [MAP](MAP.md#服务与部署候选入口)；构建成功不能证明其他平台部署成功。
- 记录执行日期、对象、命令、退出结果及未覆盖范围。旧专题中的通过数量不作为当前结果。
- `npm run preview` 已指定 `dist/client`，仅预览构建后的静态前端，不提供生产 API；联调使用前述 Vite 与本地 API 服务；`docs:*` 的依赖缺口见 [RISKS](RISKS.md#文档站命令)。
